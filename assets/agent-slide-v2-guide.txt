# 홈앤서비스 동적 보고 대시보드 v2 — 레이아웃 · 동적요소 · 디자인 설계 가이드

이 문서는 AI 에이전트가 자료를 받았을 때 "무슨 장을 어떤 레이아웃·동적 요소·CI 색상 원칙으로 설계해야 대표님이 가장 빠르고 정확하게 판단하실 수 있는가"를 결정하기 위한 기준서다.

---

## 1. 동적 보고 화면의 5대 원칙

1. **5초 판독성 (최소 폰트 20px / UI 16px 고정)**
   - 대표님은 노트북(13~15인치, 75~80% 축소)이나 회의실 대형 화면에서 보신다.
   - 1920×1080 캔버스 기준 모든 글자는 **20px 이상**이므로, 정보를 많이 우겨넣으면 즉시 답답해진다.
   - 원칙: **한 장에 숫자·메시지를 줄여서 크게 보여 주고, 자세한 내용은 호버 팝업(`notes`)·클릭 드릴다운(`drill`)·클릭 상세창(`panel`)으로 숨긴다.**
2. **결론 먼저, 숫자로 증명**
   - 제목은 명사형("10월 운영 현황") 금지. 반드시 **결론 1문장 + 핵심 숫자**로 40자 이내 작성.
   - 예: `"10월 처리율 93.1% 목표 회복, 단 재방문율(5.6%)과 경기 남부(89.4%)는 미달"`
3. **브랜드 색상 및 시각 위계 준수 (기능이 받쳐주는 디자인)**
   - **SK Red (`#EA002C`) — 문제·미달·의사결정 1곳에만 절제 사용**: 목표 미달, 악화된 증감, 1순위 원인, 의사결정 요청 배지, 목표선에만 사용한다.
   - **SK Orange (`#F47725`) — 브랜드 시그니처 포인트**: 장 번호 태그(`.tag`), 표지 메타 포인트, 2단 패널 소제목 바(`.pane-h`), 카드 번호(`.card .no`), 복합/선 차트의 핵심 추이선 등에 적용해 홈앤서비스의 브랜드 일관성을 유지한다. (골격 CSS 및 그래프 스크립트에 이미 자동 반영됨)
   - **무채색(`#1A1A1A`, `#C5CAD1`) & 달성 녹색(`#14804A`)**: 정상 추이와 일반 비교 항목은 차분한 검정·회색으로 두어 빨강·주황 강조가 돋보이게 한다.
4. **회의 중 꼬리 질문에 화면 안에서 즉시 응답**
   - 정적 보고서는 대표님이 "그래서 어디 센터가 문제야?"라고 물으면 엑셀을 다시 열어야 한다.
   - 동적 대시보드는 **대표님이 물으실 1~2단계 깊은 질문까지 미리 화면 안에 심어 둔다.**
5. **자료에 없는 것은 꾸며내지 않기**
   - 하위 센터 데이터가 없는데 드릴다운을 꾸며 넣거나, 전년 데이터가 없는데 기간 전환 버튼을 만들지 않는다.
   - 시뮬레이션(`SIMS`)은 의사결정 도구이므로 가정 계수를 투명하게 밝힌다.

## 2. 데이터 성격 → 레이아웃 선택 매트릭스

자료를 받으면 아래 표에 따라 장별 레이아웃을 고른다. **연속된 두 장에 똑같은 레이아웃만 반복하지 않도록 리듬을 만든다.**

| 자료·메시지 성격 | 최적 레이아웃 | 피해야 할 나쁜 선택 |
|---|---|---|
| 핵심 KPI 3~4개 + 12개월 추이 한눈에 | **① KPI 카드 4개** (`.kpis`) 또는 **② 대시보드 복합형** (`.kpi-strip` + 하단 차트) | 표에 숫자 15개를 한꺼번에 나열 |
| 첫 장에서 요약 숫자 + 가장 중요한 추이/현황을 동시에 | **② 대시보드 복합형** (상단 `.kpi-strip` 3~4개 + 하단 `.cols`) | KPI 따로, 그래프 따로 쪼개서 초반 리듬이 느려짐 |
| 단일 핵심 지표의 시계열·비교 + 해석 | **③ 그래프 + 우측 해석** (`.cols`) | 그래프만 꽉 채우고 해석 없음, 또는 우측에 문단 5줄 장문 |
| 원인·항목별 규모 비교 + 각 항목의 조치/담당 | **④ 그래프 + 클릭 상세창** (`.cols` + `panel`) | 표 10행에 원인·조치·담당을 작은 글씨로 구겨 넣음 |
| 서로 보완되는 두 관점 나란히 비교 (예: 전년 대비 ±증감 + 구성비, 또는 차트 + 요약 표) | **⑤ 2단 분할** (`.cols2` + `.pane`) | 한 차트에 막대 3개+선 2개를 겹쳐 판독 불가 |
| 핵심 원인 2~3개와 대응 조치의 인과관계 강조 | **⑥ 원인 → 조치 연결 흐름** (`.flow`) | 글머리표 텍스트로만 길게 서술 |
| "인원·예산·기준을 바꾸면 목표를 넘기나?" 의사결정 검증 | **⑦ What-if 시뮬레이터** (`.sim`) | "인원 보강 시 개선 기대" 같은 추상적 문장만 적음 |
| 다음 달 실행 과제 + 대표님 승인/결정 요청 | **⑧ 카드 3개 + 의사결정 띠** (`.cards` + `.decision`) | 마지막 장에 "최선을 다하겠습니다"로 끝냄 |
| 정확한 숫자 대조(목표·실적·차이·비중) | **⑨ 핵심 표** (`.tbl`, 최대 6행×5열, 문제 행 `tr.hi`) | 10행 8열 엑셀 시트를 그대로 복붙 |

## 3. 데이터 성격 → 차트 유형(5종) 선택 기준

| 보고하려는 질문 | 차트 `type` | 핵심 옵션 | 주의사항 |
|---|---|---|---|
| 항목별 크기·순위 비교, 기간 전환, 세부 드릴다운 | `bar` | `dir: "h"`(항목명 길거나 비교), `target`, `below`/`above`, `series`, `drill`, `sort`, `filterBelow` | 항목 6개 이상이거나 한글 이름이 4자 넘으면 **반드시 `dir: "h"` 가로 막대** 사용 |
| 기간별 단일/2개 지표 추이 비교 (올해 vs 전년) | `line` | `lines` (최대 2~3개), `target`, `notes`, `min`/`max` | 선이 4개 이상이면 판독 불가 → 2개(올해 vs 전년) 권장 |
| 물량(건수·매출)과 비율(처리율·이익률)의 동시 흐름 | `combo` | `barValues` + `lineValues` + `target` + `notes` | 막대는 중립 회색(핵심 1개월만 검정), 추이선은 SK Orange(`#F47725`), 목표선은 SK Red(`#EA002C`) 점선으로 자동 대비 |
| 전년·전월·목표 대비 **증감(`+` / `-`)** 비교 | `delta` | `bad: "neg"`(감소가 문제) 또는 `bad: "pos"`(증가가 문제), `sort: true` | **음수가 있는 증감은 절대 일반 `bar`에 넣지 말고 `delta`를 쓴다** |
| 전체 100% 중 항목별 **구성비·비중** 비교 (권역별·분기별) | `stack` | `segments` (최대 4~5개), 핵심 1개만 `hi: true` | 11% 미만 조각은 내부 숫자가 생략되므로 `notes` 팝업으로 정확값 확인 |

## 4. 동적 요소 9종 — 언제 쓰고, 언제 빼는가

### 4-1. 동적 요소 적용 규칙
| 동적 요소 | 대표님의 예상 질문 | 반드시 넣을 때 | 넣으면 안 될 때 |
|---|---|---|---|
| **카운트업 + 스파크라인** | "이번 달 성적표 어때?" | 1장 요약 KPI 카드 | 숫자가 단순 텍스트이거나 추이 시계열이 없을 때 |
| **호버 팝업 (`notes`)** | "이 달/이 항목 정확히 무슨 일이야?" | **모든 차트에 기본 탑재** (핵심 맥락 1줄 + 보조 수치) | 그래프에 이미 적힌 숫자만 똑같이 반복할 때 |
| **기간 전환 탭 (`series`)** | "전월이나 전년이랑 비교하면?" | 비교 기간이 2~3개(이번 달 / 분기 평균 / 전년 동월) 모두 자료에 있을 때 | 단일 시점 데이터만 있을 때 |
| **정렬 토글 (`sort: true`)** | "안 좋은 순 / 높은 순으로 세워봐" | 권역·센터·팀·상품 등 **비교 대상이 4개 이상**일 때 | 월별 시계열(`1월~12월`)에는 정렬 금지! (시간 순서가 깨짐) |
| **미달만 보기 (`filterBelow: true`)** | "목표 못 넘긴 곳만 모아봐" | `target`이 있고, 미달 항목과 달성 항목이 섞여 있을 때 | 모든 항목이 달성이거나 `target`이 없을 때 |
| **클릭 드릴다운 (`drill`)** | "여기 권역은 왜 이래? 센터별로 봐" | 상위 항목 아래 하위 데이터(권역→센터, 본부→팀)가 자료에 있을 때 | 하위 데이터가 없을 때 (지어내기 금지!) |
| **클릭 상세 패널 (`panel`)** | "이 원인 하나만 자세히, 조치랑 담당은?" | 항목마다 `무슨 일이 / 조치 / 담당·일정` 등 2~3개 속성이 있을 때 | 항목별 설명이 1줄뿐이면 `notes` 팝업으로 충분 |
| **What-if 시뮬레이터 (`SIMS`)** | "인원 10명 더 넣으면 목표 넘겨?" | 의사결정 변수(인력·예산·적용률·목표)와 예상 효과 검토가 회의 목적일 때 | 단순 과거 실적 기록 보고만 원할 때 |
| **목차 · 전체 보기 · 발표자 창** | "아까 3장 다시 봐 / 발표 노트 크게 보자" | 골격에 자동 내장 (`G` 목차, `O` 전체 보기 그리드, `D` 판서/레이저, `T` 타이머, `P` 발표자 창) | — |
| **단계별 핵심 공개 (`.step`)** | "하나씩 짚어가며 설명해 봐" | 원인→조치(`.flow-row step`), 실행 카드(`.card step`), 의사결정 띠(`.decision step`) | KPI 요약·단일 차트 장에 과도하게 적용 금지 |

### 4-2. 과잉 금지 원칙 (인지 부하 제어)
- **한 장에 주 인터랙션은 1~2개까지만.**
  - 예: 권역 비교 장에 `기간 전환(series)` + `정렬/필터(sort, filterBelow)` + `드릴다운(drill)`은 모두 하나의 그래프 상단/막대에서 자연스럽게 이어지므로 OK!
  - 반면 한 장에 `시뮬레이터 + 드릴다운 차트 + 표`를 다 때려 넣는 것은 절대 금지!
- **조작 안내 칩(`.cue`)은 실제로 작동하는 기능만 쓴다.**
  - 드릴다운이 없는 장에 "막대를 누르면 세부로 나뉩니다"라고 쓰면 신뢰가 무너진다.

## 5. 레이아웃 실패 패턴 (안티패턴) vs 올바른 교정

| 실패 패턴 (절대 금지) | 왜 실패하는가 | 올바른 교정 |
|---|---|---|
| 세로 막대에 한글 항목명 10개 ("서울 강북 권역", "경기 남부 권역"...) | 20px 글자가 서로 겹쳐 읽을 수 없음 | **`dir: "h"` 가로 막대**로 전환하고 항목명을 6~8자로 정리 |
| 월별 막대 12개 라벨을 `"2026년 10월"`로 표기 | X축 라벨 충돌 | `"26.10"` 또는 `"10월"`로 4~5자 축약 |
| 2단 분할(`.cols2`) 좌우 둘 다에 12개월 복합 차트 배치 | 좁은 폭(836px)에 12개월 축이 빽빽해짐 | 12개월 시계열은 `.cols`(1192px) 또는 단독 `.chart` 사용. `.cols2`에는 4~6개 항목 가로 막대·`delta`·`stack`·요약 표 배치 |
| `KPI 4개` + `스파크라인` + `하단 차트`를 한 장에 넣기 | 세로 높이(840px) 초과로 차트 찌그러짐 | 상단 KPI + 하단 차트 조합은 반드시 컴팩트한 **`.kpi-strip`**(스파크라인 없음) 사용 |
| What-if 시뮬레이터에 근거 없는 확신형 문구 | 대표님이 "이 숫자 근거가 뭐야?" 추궁 | 모든 출력 카드 `note`에 `"가정: ..."` 명시 + 하단 `disclaimer`에 가정 모델 안내 |
| 모든 막대에 빨강 사용 또는 달성 막대를 녹색으로 칠함 | 시선 분산, 회사 표준 위반 | 정상/달성은 회색·검정, **SK Red는 미달·핵심 문제 1곳에만** (녹색은 달성 배지에만 소량 사용) |
| 제목에 숫자가 없고 추상적 ("권역별 운영 현황") | 대표님이 5초 안에 결론을 못 잡음 | `"6개 권역 중 경기 남부(89.4%)만 목표 미달 — 화성·평택 집중"` |

## 6. 대표님 보고 추천 8~10장 아키텍처 (풀 패키지 기준)

실적 자료가 풍부할 때의 표준 흐름:
1. **표지** (`cover`): 보고 구분 · 제목 · 한 줄 핵심 요약 · 작성 부서/날짜 (다크 히어로 모션 배경 + 텍스트 로고 + SK Red→Orange 그라데이션 포인트)
2. **01 · 경영 요약** (`.kpi-strip` 4개 + 하단 `.cols` 또는 `.kpis` 4개 + `.decision` 요약): 성적표 + 이번 회의 핵심 안건
3. **02 · 연간 물량·품질 추이** (`combo` 복합 차트 + `.side`): 처리 건수(막대)와 당일 처리율(SK Orange 추이선 + SK Red 목표선)을 한눈에
4. **03 · 권역 비교 & 센터 드릴다운** (`bar` 가로 + `series` 기간 전환 + `sort` 정렬 + `filterBelow` 미달 필터 + `drill` 센터 드릴다운 + `.side`)
5. **04 · 전년 대비 증감 & 구성 진단** (`.cols2` 2단 분할 — 좌: `delta` ± 증감 양방향 막대 + 정렬 / 우: `stack` 100% 누적 구성비)
6. **05 · 재방문 핵심 원인** (`bar` 가로 + `panel` 클릭 상세 패널)
7. **06 · 원인별 개선 조치** (`.flow` 원인 → 조치 3행 연결 흐름)
8. **07 · What-if 의사결정 시뮬레이션** (`SIMS` 슬라이더 2~3개 + 보수/권장/적극 프리셋 + 실시간 목표 달성 게이지)
9. **08 · 실행 계획 & 의사결정 요청** (`.cards` 3개 + 하단 `.decision` 의사결정 요청 띠)
10. **끝 장** (`end`): 감사합니다 · 문의 부서

※ 자료가 적으면 없는 데이터를 꾸며내지 말고, 자료가 있는 4~6장만 알차게 구성한다.
